# Zapret Console

**Удобное терминальное меню для zapret в Linux.** Запуск и остановка, стратегии, сохранённые профили и диагностика Discord в одном месте.

```bash
zapret-console
```

Интерфейс на русском. Новый Textual поддерживает Tab / Shift+Tab, стрелки, Enter, мышь, F5 для обновления и Ctrl+Q для выхода. Esc отменяет диалог. Закрытие интерфейса не останавливает сервис.

Установщик 0.3.0 ставит Textual и GUI в отдельное окружение приложения и добавляет два ярлыка: окно и терминал. Системный Python не изменяется. При обновлении адаптер, сервис и профили сохраняются.

## Возможности

- Состояние сервиса, текущая стратегия, интерфейс и автозапуск на главном экране.
- Включение, остановка, перезапуск и управление автозапуском.
- Выбор стратегии из установленных файлов без ручного редактирования конфига.
- Сохранение рабочей конфигурации, восстановление профиля и отмена последнего изменения.
- Именованные профили подключений: несколько сохранённых настроек с восстановлением и удалением через меню.
- Возврат прежней конфигурации, если сервис не запустился после её изменения.
- Проверка полной загрузки страницы Discord, API и WebSocket.
- Отображение маршрута и предупреждение, если трафик идёт через другой интерфейс, например VPN.
- Просмотр журнала сервиса, проверка зависимостей и JSON-статус для скриптов.

## Поддержка

Основа 0.2.0 проверена на Ubuntu 26.04 с systemd и адаптером [zapret-discord-youtube-linux](https://github.com/Sergeydigl3/zapret-discord-youtube-linux). Требуется Python 3.10 или новее. Мастер установки поддерживает Ubuntu/Debian. Другие Linux-дистрибутивы с systemd пока считаются экспериментальными. OpenRC и другие init-системы в этой версии не поддерживаются.

Это самостоятельный интерфейс управления адаптером. Мастер может установить движок и стратегии или подключить существующую установку. Наличие подходящей стратегии зависит от подключения и провайдера; успешный запуск сервиса не подтверждает доступность Discord.

## Установка

Для Ubuntu / Debian после клонирования проекта достаточно запустить мастер:

```bash
git clone https://github.com/KrakeKrip/Zapret-discord-linux.git
cd Zapret-discord-linux
sudo bash scripts/setup.sh
zapret-console
```

Для команды `git clone` нужен установленный Git (`sudo apt install git`). Системные библиотеки и Python venv мастер установит через APT при необходимости; зафиксированные PySide6/Textual — через PyPI в окружение приложения. Для GUI нужен desktop polkit-agent (обычно есть в GNOME/KDE). Он использует зафиксированный коммит адаптера `69db771b527ba11ca71efe28728a7f9491eec352`, движок `v72.9` и рекомендованный этим коммитом набор стратегий.

Мастер определяет интерфейс обычного подключения, предлагает первый профиль и создаёт сервис. По умолчанию новый движок остаётся остановленным: включите его из меню. Чтобы сразу запустить новый сервис и включить автозапуск, передайте `--autostart`.

Существующая полная установка подключается с сохранением конфига, профиля и состояния сервиса. Если в каталоге есть неполная установка или уже работает другой `nfqws`, мастер остановится с объяснением. Повторный запуск не заменяет рабочий адаптер.

Просмотр плана без загрузок и изменений:

```bash
bash scripts/setup.sh --dry-run
```

Без вопросов (интерфейс и стратегия должны подходить вашему подключению):

```bash
sudo bash scripts/setup.sh --yes --interface eth0 --strategy general_alt11.bat --autostart
```

`general_alt11` — начальный вариант для проверки, а не универсально рабочая стратегия. После проверки профиля в Discord сохраните его через меню.

Для обновления только интерфейса поверх готового адаптера используйте `sudo bash scripts/setup.sh --yes`: мастер также проверяет зависимости GUI/TUI. Если системные зависимости уже установлены, достаточно `sudo bash scripts/install.sh`. Адаптер должен иметь `service.sh`, `conf.env`, `nfqws`, стратегии и системный сервис.

Если адаптер установлен в другом месте:

```bash
sudo bash scripts/install.sh --backend-root /opt/my-zapret --service zapret_discord_youtube.service
```

Каталог адаптера, конфигурация и исполняемый код должны принадлежать root и быть недоступны для записи обычным пользователям. Настройки подключения к адаптеру хранятся в `/etc/zapret-console/settings.json`. Приложение устанавливается в `/usr/local`; терминальные действия запрашивают пароль через sudo, графические — через polkit.

## Режимы установки

По умолчанию устанавливаются окно, терминальное приложение и оба ярлыка в меню приложений. Для машины без графической сессии:

```bash
sudo bash scripts/setup.sh --yes --ui tui
```

`--ui none` устанавливает только CLI и прежнее whiptail-меню, без PySide6/Textual. Скриптовые `--status`, `--doctor`, `--diagnose` и административный helper используют изолированный системный Python и доступны независимо от UI.

Установщик готовит новую версию в `/usr/local/lib/zapret-console/releases/<id>`, создаёт окружение по окончательному пути, проверяет импорты и только затем переключает `current`. Ошибка возвращает прежние launcher, ярлыки и настройки. Старые выпуски сохраняются, чтобы уже открытое окно продолжило работать; они занимают место и удаляются вместе с приложением. Ручное удаление выпусков при открытом GUI/TUI не рекомендуется. Обновление интерфейса не запускает и не перезапускает сервис.

Проверка упаковки без root и без загрузок:

```bash
DESTDIR=/tmp/zapret-stage bash scripts/install.sh
/tmp/zapret-stage/usr/local/bin/zapret-console --help
DESTDIR=/tmp/zapret-stage bash scripts/uninstall.sh
```

Для проверки с настоящими UI-зависимостями добавьте `--with-deps`; загрузка из PyPI идёт в staging-окружение. `DESTDIR` должен быть абсолютным. Системные файлы и родители не должны быть ссылками или доступны посторонним для записи.

## Использование

```bash
zapret-console                # Textual
zapret-console --tui          # явно открыть Textual (extra tui)
zapret-console --legacy-menu  # прежнее whiptail-меню
zapret-console --gui          # графическое окно (нужен пакет zapret-console[gui])
zapret-console --status       # состояние и текущая конфигурация
zapret-console --status --json
zapret-console --doctor       # зависимости и подключение адаптера
zapret-console --diagnose     # проверка Discord через текущий сетевой путь
zapret-console --version
```

Для запуска Textual из рабочей папки:

```bash
python3 -m venv .venv
.venv/bin/pip install ".[tui]"
PYTHONPATH=src .venv/bin/python -m zapret_console --tui
```

Для обоих интерфейсов установите `".[gui,tui]"`. Textual содержит пять разделов: состояние, профили, стратегии с поиском, диагностика и журнал. Он работает без DISPLAY и через SSH. При системном действии интерфейс временно возвращает терминал sudo, затем восстанавливается; пароль получает sudo. Старые `--status`, `--json`, `--doctor`, `--diagnose` не требуют Textual или Qt.

GUI и TUI используют общий клиент и блокировку. Если другое окно изменило файлы после открытия формы, операция отклоняется; интерфейс обновляет данные и ждёт нового подтверждения. Автоматического повтора нет. Закрытие во время операции ждёт её завершения. Минимальный проверенный размер терминала — 80×24; содержимое прокручивается. Копирование отчётов использует OSC 52 и зависит от терминала.

Системные действия из исходников требуют launcher 0.3.0 с JSON-протоколом. Обновите прежнюю установленную версию командой `sudo bash scripts/setup.sh --yes`.

Графическое окно (экспериментально) содержит разделы «Главная», «Профили», «Стратегии», «Диагностика» и «Журнал», работает с обычными правами и запрашивает авторизацию через polkit при изменениях. Для запуска из исходников:

```bash
python3 -m venv .venv
.venv/bin/pip install ".[gui]"
.venv/bin/python -m zapret_console --gui
```

При смене стратегии сохраняются интерфейс и параметры GameFilter. Если сервис работал, меню перезапустит его; если был остановлен, он останется остановленным. Изменения выполняются по одному. При неудачном перезапуске конфигурация возвращается, но сетевую доступность нужно проверить отдельно.

Результат CLI-диагностики сохраняется в `~/.local/state/zapret-console/diagnostics.txt` или в каталоге из `XDG_STATE_HOME`. Она отдельно показывает состояние systemd, наличие `nfqws` в сервисе, правила перенаправления и подключение обработчика очереди. Проверка firewall может запросить sudo. Если права недоступны, результат обозначается как «не удалось проверить».

Счётчик очереди сравнивается до и после сетевых проб. Он общий и может включать трафик других приложений. Нулевой или недоступный счётчик не считается доказательством обработки трафика. Проверка через другой интерфейс, например VPN, не подтверждает работу zapret через обычное подключение. Голос и трансляция проверяются подключением к каналу в Discord; приложение не авторизуется в аккаунте Discord.

Сохранённый профиль и предыдущая конфигурация находятся в `/var/lib/zapret-console`; именованные профили — в подкаталоге `profiles`.

Для разных подключений (например, домашнего и мобильного) удобно хранить несколько именованных профилей в разделе «Профили» (в прежнем меню: «Сохранённый профиль» → «Именованные профили»). Текущая настройка сохраняется под именем, выбранный профиль восстанавливается целиком — со стратегией, интерфейсом, GameFilter и бэкендом firewall, — а замена и удаление требуют отдельного подтверждения. Имя: 1–48 символов, латинские буквы и цифры, внутри также `_` и `-`. Именованные профили не удаляются вместе с интерфейсом и не заменяют рабочий профиль с отменой последнего изменения. Отчёты остаются локальными; приложение ничего не отправляет в GitHub автоматически.

## Обновление и удаление

```bash
git pull --ff-only
sudo bash scripts/setup.sh --yes
```

Повторная установка сохраняет настройки подключения и профиль. Удаление интерфейса:

```bash
sudo bash scripts/uninstall.sh
```

Удаление оставляет адаптер, сервис, его конфигурацию и сохранённые профили.

## Разработка

```bash
python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m zapret_console --help
```

CI проверяет тесты, Python-код, shell-скрипты, установку в staging-каталог и удаление. Сетевой обход и голосовые подключения в CI не проверяются. Подробнее: [CONTRIBUTING.md](CONTRIBUTING.md).

### Диагностика и журнал в графическом окне

«Проверить Discord» проверяет страницу приложения, API и WebSocket, маршрут и состояние сервиса/движка/firewall/очереди. Проверка запускается вручную, без входа в аккаунт и без изменения сетевых правил. По умолчанию пароль не запрашивается; недоступные данные помечаются как неизвестные. Опция «Проверить firewall с правами администратора» использует системную авторизацию через общий helper — она может потребоваться до сетевой проверки и после неё. Отмена не запускает повторный запрос автоматически.

«Журнал» читает до 100 последних записей сервиса с текущими правами пользователя. Подсказки об ограничении доступа показаны рядом с журналом. Текст отчёта и журнала можно выделить или скопировать кнопкой. Предыдущий завершённый результат остаётся видимым при новом чтении. Проверки выполняются вне GUI-потока; закрытие окна дожидается текущей работы, сервис продолжает работать. Успех сетевых проб, особенно через VPN, не подтверждает обход через обычное подключение, голос или трансляцию.
