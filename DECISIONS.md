# Технические решения

## D-001: Отдельный интерфейс поверх адаптера

Zapret Console управляет существующим Linux-адаптером вместо собственной реализации сетевого движка. Это позволяет развивать пользовательские сценарии без дублирования nfqws и стратегий. Последствие: совместимость зависит от контракта адаптера; замена адаптера требует отдельной задачи.

## D-002: Python и whiptail

CLI и логика реализованы на Python 3.10+; текущий терминальный интерфейс использует whiptail. У тестов нет сторонних зависимостей. Это исходное решение для версии 0.2.0; последующее направление GUI/TUI описано в D-006.

## D-003: Ограниченные привилегированные действия

Меню вызывает установленный launcher через sudo для конкретных административных действий. Настройки, код адаптера и родительские каталоги проверяются на доверенность. Запуск всего пользовательского сценария с root расширил бы объём привилегированного кода.

## D-004: Сохранение установки и осторожная диагностика

Мастер подключает готовую установку без замены. Новая установка использует закреплённый commit адаптера вместо произвольного последнего состояния. Диагностика отдельно оценивает сервис и сеть: успешный HTTP/WebSocket через VPN не считается подтверждением обхода. Автоматическое обновление и выбор стратегии потребуют отдельных критериев проверки и восстановления.

## D-005: Последовательная работа Codex и GLM

Codex отвечает за архитектуру, TASK, ключевые документы, review и commit. GLM реализует конкретный TASK и выполняет самопроверку; пользователь передаёт задания и отчёты. Одновременно репозиторий изменяет только один агент. Codex самостоятельно проверяет diff и релевантные проверки перед приёмкой; GLM не делает commit/push. Push выполняется только по прямому указанию пользователя.

## D-006: Два интерфейса и общий слой управления (план)

По запросу пользователя GUI будет использовать PySide6 / Qt Quick (QML), терминальный интерфейс — Textual. QML выбран для собственного оформления и переходов; Qt Widgets — более простой вариант привычного настольного UI, но для выбранного направления уступает по свободе оформления. Дополнительный слой QML и зависимости принимаются как цена этого решения; версии и упаковка определяются в соответствующих TASK.

Общую логику выделяем до создания интерфейсов, чтобы не дублировать операции и проверки безопасности. Административный путь остаётся единым, с общей межпроцессной блокировкой и последующей проверкой ожидаемого состояния для защиты от устаревших сохранений. Блокировки каждой отдельной UI-копии не защитили бы общий конфиг; отдельный постоянный daemon пока добавил бы ненужную сложность. GUI и TUI работают без root; авторизация выполняется только для запрошенных системных действий.


## 2026-10-09 — актуальный продукт и перенос разработки

- Название Zapret Manager; команда и package paths zapret-console сохранены ради совместимости.
- По решению владельца Textual удалён. Основные UI: PySide6/QML и простое whiptail-меню. Историческое решение TASK-005 отменено TASK-007.
- Интерфейс и движок — разные компоненты. install.sh обновляет только интерфейс даже без backend; setup.sh может создать backend. Удаление движка допускается только как отдельная явно запрошенная операция с архивом.
- Восстановление архива поддерживает hard links внутренних списков, создаваемые адаптером, с проверкой цепочек до записи. Старое стороннее меню не возвращается.
- Файлы выпуска 0.3.2 доступны через Releases и GitHub Packages/GHCR. GitHub Packages не предоставляет PyPI-реестр, поэтому GHCR-образ хранит wheel/sdist/полный архив и не запускает сетевой обход в контейнере.
- AGENTS.md и HANDOFF.md — начало работы на новом устройстве. Состояние host, SSH, sudo и архивы не считаются переносимыми вместе с исходниками. Подробные отчёты — в файлах, в чат — короткий итог.
