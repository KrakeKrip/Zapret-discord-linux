# TASK-005 — Textual: итог Codex

Статус: завершён. Дата: 2026-10-09. Baseline: 65a70b3. Исполнитель: Codex самостоятельно по указанию пользователя; GLM не привлекался.

## Результат

Реализовано терминальное приложение Textual 8.2.8 (опциональный extra `tui`), пять разделов:

- Главная: состояние, стратегия/интерфейс, явные start/stop/restart и включение/выключение автозапуска.
- Профили: список с пометкой повреждённых, сохранение, восстановление, подтверждённые замена и удаление. Имя проверяется до авторизации; Enter в подтверждении по умолчанию отменяет действие.
- Стратегии: поиск, текущая стратегия отдельной строкой, применение выбранной. Пустой выбор и текущая стратегия не применяются.
- Диагностика: общий сетевой отчёт, явная опция расширенного чтения firewall через sudo.
- Журнал: последние записи и подсказки ограниченных прав. Журнал и отчёт — буквальный текст, копирование через OSC 52 при поддержке терминала.

Запуск без флага или `--tui`, прежнее меню — `--legacy-menu`. TUI требует обычного пользователя и интерактивных stdin/stdout, работает без DISPLAY. CLI-режимы и импорт client не загружают Textual или PySide6. Поддерживаются клавиатура, мышь, F5 и Ctrl+Q; минимальный проверенный размер 80×24, большие панели прокручиваются.

## Общая логика и совместная работа с GUI

`client.Backend` — единый адаптер чтения/запросов для обоих интерфейсов. GUI сохраняет свой default mode=gui и pkexec; TUI использует mode=terminal и sudo. Core, helper, протокол и правила доверенности не менялись.

Блокирующая работа выполняется asyncio.to_thread, виджеты меняются только в цикле Textual. Одна pending task запрещает пересекающиеся локальные операции. Перед sudo App.suspend() возвращает нормальный терминал; ввод пароля получает sudo. После операции интерфейс восстанавливается.

Диалог фиксирует revision при открытии. Фоновое чтение не подменяет этот токен. Conflicts/busy не повторяются автоматически; после мутации состояние перечитывается, сообщение о конфликте сохраняется. Неполный snapshot отключает файловые операции. При восстановлении чтения сообщение об ошибке заменяется успешным результатом.

Обычное закрытие прекращает polling и приём новых задач, ждёт текущую операцию, затем выходит. Закрытие не отправляет stop сервиса.

- Базовый Python без UI-библиотек: 172 теста, OK, skipped=46 (опциональные GUI/TUI и wheel без setuptools).
- 12 новых TUI тестов: режимные guards, root/TTY guards, чистые импорты, работа без DISPLAY в 80×24, видимость результата над Footer, пустой поиск/выбор, revision формы, отмена, невалидное имя/потеря revision, безопасный focus замены/удаления, busy и закрытие, буквальный журнал/диагностика, недоступное чтение/восстановление, suspend на UI-потоке при запросе из worker, совместная работа Qt bridge и Textual.

Данные, endpoint, CAS, атомарные записи и flock настоящие в временной установке; только root identity, trusted и systemctl подменены. Реальная система не менялась.
- Wheel-тест расширен: пакет включает все три TUI модуля и прежние QML-ресурсы. Сборка прошла в полном venv suite.
- `python3 -m compileall -q src`, `bash -n scripts/install.sh scripts/uninstall.sh scripts/setup.sh`, `PYTHONPATH=src python3 -m zapret_console --help`, `bash scripts/setup.sh --dry-run`, `git diff --check` — OK.
- Сняты пять экранов в 80×24, просмотрены PNG. Исправлены перекрытие Footer и строки результата, а также использование старого Select.BLANK: в Textual 8.2 используется Select.NULL. Оба сценария покрыты pilot-проверкой. При переполнении главной прокрутка предусмотрена.
