# TASK-008 — Восстановление движка и меню без подключённого backend

Дата: 2026-10-09. Пользователь явно разрешил восстановить рабочий движок из резервной копии, сохранив управление через Zapret Manager.

## Реализация

scripts/restore-backend.py требует sudo и --restore-backend. Выбирает последнюю legacy-*.tar.gz в защищённом /var/backups/zapret-console. Проверяет архив и системные родители через общий check_path. Не заменяет существующий движок или unit. Архив на host без root прочитать невозможно; его фактическое содержимое проверяется при привилегированном запуске.

Из архива выбираются только /opt/zapret-discord-youtube-linux и /etc/systemd/system/zapret_discord_youtube.service. До записи проверяются пути, типы объектов, отсутствие дубликатов, обязательные conf.env/nfqws/service.sh и подходящий unit. Ссылки и специальные файлы отклоняются. Распаковка выполняется вручную в временный каталог внутри /opt, без extractall; каталог публикуется rename после проверки. Файлы принадлежат root:root, групповые/мировые write и специальные permission bits убираются. Сохранённый конфиг и стратегии восстанавливаются из архива. Старый zapret-menu и состояние собственного продукта не извлекаются.

После восстановления: daemon-reload, start, is-active. Автозапуск принудительно не включается. Если systemd-запуск не удался, восстановленные файлы остаются для диагностики; успех не объявляется. Состояние active не приравнивается к доступности Discord.

Дополнительно исправлен случай исходного терминального меню: при отсутствующем движке или неполной установке вместо аварийного выхода открывается read-only экран с подробностями, повторной проверкой и выходом. Системных действий и автоматической установки движка нет. CLI --doctor сохраняет прежний error exit. Версия исходников 0.3.2; host-обновление этой версии отдельно не выполнено. После восстановления backend установленное меню 0.3.1 сможет пройти свою исходную проверку.

## Проверки

- Полная .venv unittest suite: 204 теста OK, skipped=1; Qt/QML stderr чистый.
- Пять новых restore-тестов: выбранные файлы и прежняя стратегия, исключение меню/профилей, опасные пути/ссылки/устройства и неполный архив до записи, sandbox восстановление с подменёнными chown/systemctl, отказ замены существующего backend, отказ без root.
- Два новых menu-теста: отсутствие backend открывает экран без sudo и без чтения несуществующего config; подробности/повторная проверка возвращают главное меню после появления backend.
- compileall, синтаксис restore скрипта совместим с Python 3.10, git diff --check — OK.
