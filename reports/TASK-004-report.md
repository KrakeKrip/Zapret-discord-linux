## Реализовано

**Зависимость и упаковка.** `pyproject.toml`: optional extra `gui = ["PySide6==6.12.0"]`; package data — `zapret_console/gui/qml/*.qml` + `qmldir`. Установщик и системная упаковка не менялись (по scope); из установленной в /usr/local копии `--gui` даёт понятную инструкцию вместо traceback.

**`src/zapret_console/gui/`** — новый пакет:
- `__init__.py` — без импортов Qt: обычные команды, core/client и тесты работают без PySide6; Qt загружается только в режиме `--gui`.
- `bridge.py` — QObject-мост: `OperationWorker` (один QThread с очередью; ошибки job не теряются, а доставляются сигналом `failed`), `ProfilesModel`/`StrategiesModel` (QAbstractListModel: имя/стратегия/интерфейс/повреждён/ошибка; имя/текущая), `RealBackend` (тонкий адаптер над `client.snapshot`/`core.strategies`/`client.request(mode='gui')` — второй реализации backend нет), `BackendBridge` со свойствами для QML (состояние сервиса/автозапуска текстом и тоном, интерфейс, стратегия, `canMutateFiles`, `revision`, `revisionError`, `configError`, `busy`, `closing`, `lastEvent`, модели, подсказка имени профиля) и действиями.
- Ключевые контракты моста: файловые операции получают **revision показанного состояния** — диалоги замены/удаления и поле сохранения фиксируют `baseRevision` при открытии (императивно, не binding), авто-обновление её не подменяет; проверка поколений snapshot — поздний устаревший ответ отбрасывается; перекрывающиеся чтения запрещены; `busy` блокирует новые мутации; после любого результата — refresh; conflict показывается и обновляет данные без автоповтора; `revision=None` отключает файловые операции с показом `revision_error`, сервис-действия остаются; периодическое чтение 3 с (QTimer), ручное «Обновить» (`refreshManual` → «Состояние обновлено.»); `request_close()` при простое закрывает сразу, при операции — показывает ожидание и выходит после ограниченного результата клиента (quit-колбэк инъекцируется для тестов), поток не уничтожается во время работы.
- `app.py` (`run_gui`): отказ под root → PySide6 недоступен → инструкция установки (venv + `.[gui]`) → QGuiApplication + QQmlApplicationEngine + контекстное свойство `bridge` → загрузка `qml/Main.qml` → `bridge.start()` → exec.
- `qml/Main.qml` — окно 1040×720, минимум 800×560; слева навигация (Главная/Профили/Стратегии), сверху заголовок и чипы состояния, снизу последнее событие; тёмная спокойная палитра с сине-зелёным акцентом (`Theme.qml` singleton + `qmldir`), русские подписи, системный шрифт, статусы текстом+цветом. «Главная»: сервис/интерфейс/стратегия/автозапуск, явные Запустить/Остановить (не toggle), Перезапустить, Включить/Выключить автозапуск, ошибка конфигурации видна. «Профили»: список с пометкой «повреждён» и ошибкой, сохранить (диалог с валидатором имени RegExpValidator + подсказка ограничений), восстановить (недоступно для повреждённого), заменить и удалить только после подтверждения, пустое состояние с действием. «Стратегии»: поиск по имени, отметка «текущая», применение через `strategy` (интерфейс/GameFilter/firewall не меняются). Все мутации `enabled: !busy && !closing` (+ `canMutateFiles` для файловых), BusyIndicator-оверлей, диалоги сообщений по сигналам моста.

**CLI (`app.py`).** `--gui`: несовместимость с human-режимами → `parser.error`; с `--request-json` → `invalid_request` (машинный контракт сохранён); Qt и модуль gui импортируются только в ветке `--gui`; без PySide6/без gui-модулей — инструкции установки и exit 1; под root — отказ с предложением обычного запуска. Остальные режимы не тронуты.

**Документация.** README: `--gui` в списке команд + блок «графическое окно (экспериментально)» с командами venv; CONTRIBUTING: раздел «GUI (экспериментально)» с запуском и headless-командами тестов.

## Тесты (18 новых, всего 128; PySide6-тесты пропускаются без extra)

`BridgeTests` (12, QCoreApplication + FakeBackend с инъекцией): асинхронное применение snapshot/стратегий; ошибка чтения → «Неизвестно» с тоном warn, файловые операции отключены, сообщение; `revision=None` → `canMutateFiles=False` с `revision_error`; генерационный guard отбрасывает устаревший ответ; **сценарий двух клиентов**: подтверждённое удаление уходит с показанной revision, конфликт показан, ровно один запрос, повторов нет, refresh выполнен; подтверждение использует revision диалога, а не свежую (данные изменились вне окна — запрос ушёл со старой); сервис-действия явные start/stop/restart/enable/disable без revision; busy блокирует вторую операцию; профиль-операции передают имена и revision; фильтр стратегий и `applyStrategy`; закрытие: простое — сразу, во время операции — ожидание и quit после результата; ошибка операции показывается сообщением. `QmlLoadTests`: Main.qml загружается с нулём QML-предупреждений (поймал и я им исправил реальный TypeError `bridge.profiles.count` — модели теперь объявлены как Property). `GuiCliTests`: `--gui --status` → usage-ошибка; `--request-json {} --gui` → `invalid_request`; root-запуск → отказ; без PySide6 → инструкция. `PackageDataTests`: локальная сборка wheel (`pip wheel --no-deps --no-build-isolation`) содержит `qml/Main.qml`, `Theme.qml`, `qmldir`.
