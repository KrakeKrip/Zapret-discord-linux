## 1. Проверка доверенности каталога при создании профиля

Файл: `src/zapret_console/app.py`, profile_op / check_profiles_dir.

Сейчас profile-save проверяет только отсутствие символических ссылок и занятого имени. При существующем profiles обычный каталог не проходит trusted(): запись нового файла выполняется в том числе в каталог с недоверенным владельцем или правами. Для restore/replace/delete trusted(path) проверяет родителей, для save такой проверки нет.

Воспроизведение Codex: существующий каталог profiles; config() возвращает валидный объект; trusted подменён отказом RuntimeError. profile_op('profile-save', 'home') всё равно создаёт файл, trusted не вызывается ни разу.

Исправление:
- Перед созданием нового файла проверять существующий каталог profiles через trusted().
- Если каталог отсутствует, проверять доверенность STATE перед созданием; создавать каталог с правами, допускающими чтение обычным пользователем, и проверять его перед записью.
- Сохранить ранний отказ для символических ссылок. Проверки административной операции должны работать независимо от UI.

Приёмка: отказ trusted для существующего каталога не создаёт файл и не меняет conf.env. Отсутствующий profiles нормально создаётся в доверенном STATE. Добавить тест проверки владельца/прав каталога существующим trusted; можно точечно подменить сведения stat для конкретного каталога, сохранив саму функцию trusted. Не ограничиваться mock всей функции во всех тестах защиты.

## 2. Чтение списка следует за ссылкой вместо каталога

Файл: `src/zapret_console/app.py`, profile_entries.

profile_entries сначала вызывает d.is_dir(), затем d.iterdir(), но не проверяет d.is_symlink(). Ссылка STATE/profiles на внешний каталог позволяет показать внешние JSON как профили. Административные операции эту же ссылку отклоняют.

Воспроизведение Codex: STATE/profiles — ссылка на соседний каталог с external.json. profile_entries возвращает external вместо отказа.

Исправление: чтение списка должно отклонять ссылку вместо каталога до перечисления файлов, включая dangling symlink. Использовать общий механизм проверки без запроса sudo. Меню должно показать понятную ошибку.

Приёмка: внешний каталог не перечисляется; нормальный каталог читается без sudo; отсутствующий каталог по-прежнему возвращает пустой список. Добавить тесты реальных ссылок для profile_entries и обработки ошибки в меню, не только profile_op. Существующие защиты от ссылок вместо файлов сохранить.

## 3. Нормализованное имя не используется после проверки

Файл: `src/zapret_console/app.py`, profiles_menu, ветка save.

Код проверяет profile_path(name.rstrip('\n')), но затем использует исходное name для target и privileged. Поэтому заявленная обработка завершающего newline не работает.

Воспроизведение Codex: dialog возвращает 'mobile\n'. Меню вызывает privileged('profile-save', 'mobile\n'), и повторная административная проверка отклоняет это имя. Для занятого имени также выбирается неправильный путь проверки существования.

Исправление: если сохраняется нормализация завершающего newline, присвоить нормализованное имя и использовать один результат в валидации, проверке существования, подтверждении и вызове launcher. Не использовать strip(), который молча разрешит запрещённые пробелы. Административная операция продолжает строго отклонять исходные недопустимые имена.

Приёмка: 'mobile\n' из dialog передаётся как 'mobile'; 'home\n' для существующего home предлагает замену; отмена замены не вызывает launcher. Пробелы и newline внутри имени по-прежнему отклоняются. Добавить соответствующие UI-тесты.
