# TASK-004 — Первое графическое приложение PySide6 / QML

Рабочая папка `/home/atlkhnv/Zapret-discord-linux`. TASK-003 принят commit `4f2c9a0`: общий core, read-only snapshot, revision, клиент sudo/pkexec и структурированные результаты готовы. Новый GUI работает с обычными правами, общим клиентом и общей блокировкой.

До подготовки TASK оставался untracked `reports/TASK-002-report.md` от предыдущей задачи: не удалять, не менять, не считать своим.

## Цель

Рабочее графическое окно с тремя законченными разделами: «Главная», «Профили», «Стратегии». Запуск из исходников через `python -m zapret_console --gui`; существующие CLI/whiptail сохраняются. Диагностика и журнал в GUI будут отдельным продолжением, без пустых заглушек в этом окне.

## Решения Codex

- Python + PySide6, Qt Quick/QML, Qt Quick Controls. Новый пакет gui/ с Python-мостом/worker и QML-ресурсами. Не смешивать QObject с core/client и не реализовывать второй backend.
- Дополнительная зависимость только в optional extra `gui`: `PySide6==6.12.0`. Официальный PyPI на момент подготовки содержит Linux wheels, Python >=3.10,<3.16. Источник: https://pypi.org/project/PySide6/ . Если пакет несовместим с фактической средой, сообщить blocker с доказательством, не выбирать другой стек самостоятельно.
- QML-файлы включить в package data. Системную упаковку `/usr/local`, ярлык и установщик не менять: это отдельный этап. Для разработки использовать локальный venv, без sudo/pip --break-system-packages.
- Загрузка Qt только в режиме --gui, чтобы прежние команды, core/client и unittest без GUI-extra работали без PySide6/DISPLAY.

## Что сделать

1. Добавить --gui и отдельную точку запуска окна. Несовместимые режимы отклоняются без административных операций; поведение --request-json сохраняется. При отсутствии GUI-extra — понятная инструкция установки. Запуск GUI под root отклонять с предложением запуска обычным пользователем.
2. Окно по умолчанию около 1040x720, минимальный размер 800x560. Слева боковая навигация, сверху название и состояние, снизу последнее событие. Русские подписи, системный шрифт, спокойная тёмная палитра с одним сине-зелёным акцентом. Статусы выражать текстом и цветом, не цветом одним. Нормальная читаемость на HiDPI и при изменении размеров; Tab/Enter/Esc и явный фокус.
3. «Главная»: состояние сервиса (включая unknown/ошибку), интерфейс, стратегия, состояние автозапуска; действия Запустить/Остановить (передавать явный start/stop, не toggle), Перезапустить, настройка автозапуска. Запуск окна не меняет состояние сервиса. Закрытие окна не вызывает stop/disable.
4. «Профили»: список имени/стратегии/интерфейса с пометкой повреждённого файла. Сохранить текущую настройку, восстановить выбранную, заменить после подтверждения, удалить после подтверждения. Ограничения имени существующие. Пустое состояние с понятным действием, повреждённый профиль можно удалить/заменить, но не восстановить.
5. «Стратегии»: список установленных стратегий с поиском по имени и отметкой текущей; применение через client.request с action strategy. Не изменять интерфейс/GameFilter/firewall напрямую.
6. snapshot/список стратегий и client.request выполнять вне потока GUI через worker. Результаты передавать signals, QML/model изменять только в GUI-потоке. Интерфейс остаётся доступен во время медленного чтения/авторизации/systemctl. Ошибки workers не приводят к тихому исчезновению результата.
7. При операции показать прогресс, отключить повторные изменения в этом окне, не запускать одинаковые действия несколько раз. После любого результата перечитывать snapshot. busy/conflict/auth_cancelled/auth_failed/operation_failed/transport_error показывать понятными сообщениями; conflict не повторять автоматически, запросить обновление и новое подтверждение пользователя. Timeout/transport_error не выдавать за отмену или успех.
8. Каждая файловая операция использует revision именно показанного пользователю состояния, включая подтверждение замены/удаления. Не подменять её свежей revision перед отправкой. Если snapshot обновился во время формы/подтверждения, сохранить прежний базовый token для действия либо явно отменить форму и попросить подтвердить заново. Нельзя автоматически переносить подтверждение удаления/замены на изменившийся профиль.
9. Периодическое чтение примерно раз в 3 секунды (без перекрывающихся snapshot-запросов), плюс ручное обновление и refresh после действия. Старый медленный ответ не должен перезаписывать более новое состояние; предусмотреть номера запросов/поколений. Если состояние недоступно, показать причину, не отображать «остановлен» вместо unknown.
10. При revision=None файловые изменения недоступны с объяснением revision_error; явные сервис-действия допускаются при наличии рабочего клиента. Не хранить состояние сервиса отдельно в GUI как источник истины.
11. При закрытии во время операции GUI не посылает stop и не убивает helper как способ отмены мутации. Безопасно завершить worker: не уничтожать работающий QThread; запрос закрытия может дождаться ограниченного client timeout, сохраняя отзывчивость и показывая ожидание. Не обещать отмену уже отправленной операции.
12. Добавить краткие команды локального запуска в README/CONTRIBUTING; в тестах мост получает подменяемый backend/transport, но обычное приложение показывает реальные данные, без скрытого demo-режима.

## Scope и ограничения

Входит: GUI, Python-мост, --gui, optional dependency/package data, релевантные тесты и инструкции разработки. Допустимы только необходимые изменения существующего CLI для выбора режима.

Не входит: Textual, system tray, autostart GUI, диагностика/журнал GUI, автоматический подбор стратегии, изменение core/client-контрактов, установка в систему или polkit-политики. Не добавлять pywebview/Electron/веб-сервер. PRODUCT/ARCHITECTURE/TASKS/DECISIONS/TASK не редактировать.

Не менять реальную установку, сервис или firewall для тестирования. Mocked-действия обязательны для функциональных тестов. GUI не собирает пароли: client(mode='gui') использует существующий polkit-агент.

## Критерии приёмки

1. --gui открывает настоящее QML-окно, оно читаемо и не выдаёт QML binding/import errors. Три раздела работают; нет неработающих кнопок/пустых вкладок.
2. Главная и списки отображают реальные snapshot/strategies; в тестах используются подмены. Закрытие не останавливает сервис.
3. Все изменения идут через client, mode=gui, с правильным action/value/revision. Подтверждения и отмена покрыты тестами, нет автоматических повторов и свежего token вместо подтверждённого старого.
4. Тест «два клиента»: данные меняются вне окна; GUI обновляется, а устаревшая подтверждённая операция даёт conflict и не повторяется. Достаточен подменяемый backend, реальных системных действий не выполнять.
5. Медленные операции не блокируют GUI, повторная команда не отправляется, поздний устаревший snapshot не откатывает новый экран. Закрытие во время worker не вызывает crash/системную остановку.
6. Существующие 110 тестов сохраняются; GUI-зависимость не обязательна для обычных тестов, --help/--status/--request-json и core/client.
7. QML включён в собранный Python-пакет. GUI-extra установлен только в локальный venv; инструкции содержат фактические команды.
