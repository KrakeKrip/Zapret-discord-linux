# Архитектура

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `src/zapret_console/app.py` | CLI, whiptail-меню, форматирование статуса и сетевые пробы |
| `src/zapret_console/core.py` | BackendContext, конфигурация, профили, проверки доверенности и единая точка административных изменений admin_command |
| `src/zapret_console/client.py` | Snapshot без root; транспорт fixed launcher через sudo/pkexec; проверка протокола и результатов |
| `src/zapret_console/gui/` | Опциональное окно PySide6/QML, модели и worker поверх общего client |
| `src/zapret_console/diagnostics.py` | Снимки процесса, firewall и NFQUEUE; интерпретация результатов |
| `src/zapret_console/setup.py` | План установки, подключение существующего адаптера, загрузка и регистрация нового |
| `scripts/setup.sh` | Запуск мастера из исходников, подготовка Python |
| `scripts/install.sh`, `scripts/uninstall.sh` | Установка и удаление интерфейса управления |
| `tests/` | unittest с временными каталогами и подменой системных операций |

Меню вызывает установленный launcher через sudo для системных действий. CLI передаёт явный BackendContext в core; admin_command проверяет root, доверенность и удерживает общий STATE/.lock до завершения изменений, перезапуска и возможного восстановления. Read-only runtime не требует блокировки. Core не выводит сообщения и не вызывает UI; импорт и создание контекста не выполняют системных действий. Адаптер управляет nfqws и правилами сети через свой systemd-сервис. Мастер использует зафиксированный commit адаптера; сторонний код и стратегии не хранятся в этом репозитории.

## Данные и установка

| Путь по умолчанию | Назначение |
| --- | --- |
| `/usr/local/bin/zapret-console` | Launcher с изолированным запуском Python |
| `/usr/local/lib/zapret-console` | Установленный пакет |
| `/etc/zapret-console/settings.json` | Путь адаптера и имя сервиса |
| `/opt/zapret-discord-youtube-linux/conf.env` | Параметры адаптера |
| `/var/lib/zapret-console` | Сохранённый и предыдущий профили, блокировка изменений |
| `/var/lib/zapret-console/profiles/<name>.json` | Именованные профили с пятью полями конфигурации; каталог создаётся при первом сохранении |
| `$XDG_STATE_HOME/zapret-console/diagnostics.txt` | Локальный отчёт; без XDG_STATE_HOME используется `~/.local/state` |

Путь адаптера и сервис настраиваются; значение сервиса по умолчанию — `zapret_discord_youtube.service`.

## Контракты и ограничения

- `conf.env` разбирается как данные, без shell eval. Входные значения проверяются до записи.
- Привилегированные операции проверяют владельцев и права файлов; изменения сериализуются через flock. Конфигурация записывается атомарно.
- Именованные профили сохраняются атомарно через административные операции под общей блокировкой. Имя ограничено ASCII, ссылки вместо каталога/файла отклоняются; создание проверяет доверенность каталога. Список читается без sudo, повреждённые файлы помечаются как недоступные. Старые known-good.json и previous.json сохраняют свой формат и поведение.
- Snapshot содержит данные и SHA-256 revision исходных байтов конфигурации/профилей; при неполном чтении или невалидной текущей конфигурации revision=None и revision_error объясняет проблему. Файловые запросы нового протокола сравнивают expected_revision под общей блокировкой до записи; несовпадение даёт conflict, непригодный snapshot — operation_failed.
- Внутренний endpoint --request-json v1 принимает только фиксированные action/value/expected_revision, не пути или команды. Stdout содержит один объект protocol/ok/code/message/data; exit 0 для ok, 1 для ошибки. Client проверяет schema/ok/code/exit, не повторяет мутации. Terminal использует sudo с TTY; GUI — pkexec без текстового fallback. Timeout/неясный результат требует перечитать состояние. Legacy --admin не требует revision ради совместимости.
- Изменение конфигурации перезапускает только ранее активный сервис; при ошибке возвращает старую конфигурацию и пытается восстановить работу.
- Мастер подключает готовый адаптер без замены; неполная установка требует устранения проблемы. Новый адаптер готовится во временном каталоге перед регистрацией.
- Диагностика использует systemd/cgroup, `/proc`, nftables либо iptables и сетевые пробы. Отсутствие прав не считается отсутствием работающего движка.
- Счётчики очереди общие для трафика; сетевые пробы не проверяют авторизацию, голос или трансляции Discord.

## Проверки

Из корня репозитория:

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q src
bash -n scripts/install.sh scripts/uninstall.sh scripts/setup.sh
PYTHONPATH=src python3 -m zapret_console --help
bash scripts/setup.sh --dry-run
```

Отдельный линтер не настроен. CI дополнительно проверяет установку и удаление с `DESTDIR`, на Python 3.10/3.12/3.14. Реальный обход блокировок и голосовые подключения в CI не проверяются.

## GUI и дальнейшая миграция

TASK-004 принят: --gui лениво загружает PySide6/QML. Главная, профили и стратегии работают через client(mode=gui) в одном worker-потоке; модели меняются в GUI-потоке. Диалоги сохраняют показанную revision; конфликты не повторяются автоматически. Закрытие останавливает таймер и приём заданий, ждёт QThread.finished через signal, затем завершает приложение; QML уничтожается прежде моста. Сервис при закрытии продолжает работать.

Textual, desktop-ярлык и системная установка зависимостей остаются отдельными задачами. Core и прежний CLI независимы от Qt; отдельный daemon не планируется. Общие lock/revision обеспечивают согласованность изменений нескольких клиентов.

TASK-004B: diagnostics.collect_diagnostics и journal_snapshot — общий слой чтения для CLI и client; не импортируют UI и не сохраняют файлы автоматически. CLI сохраняет свой diagnostics.txt. GUI запускает client.diagnose/client.journal в существующем worker; busy исключает локальное пересечение мутаций и проверок, poll сохраняет результат последней операции. Расширенное runtime-чтение явно использует существующий endpoint runtime через pkexec; без опции читает доступные данные без авторизации. Журнал использует фиксированный unit, ограниченный лимит и argv без shell; подсказки stderr не скрываются. Текст показывается как PlainText. Shutdown инспекций использует тот же sentinel/QThread.finished, не вызывает stop сервиса.
