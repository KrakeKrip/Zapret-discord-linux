# Работа агента в Zapret Manager

## Начало с нового устройства

1. Прочитайте README.md, HANDOFF.md, CONTRIBUTING.md, ARCHITECTURE.md и последние записи CHANGELOG.md. HANDOFF.md описывает актуальное состояние; tasks/ и reports/ содержат историю, которая может быть устаревшей.
2. Выполните git status --short, git log -8 --oneline, git remote -v. Не считайте пути, sudo-авторизацию, SSH-ключи, конфиг, движок или сервис на предыдущем компьютере доступными здесь.
3. Создайте локальную .venv по CONTRIBUTING.md. Сначала запустите проверки без изменения host. Настройка GUI не требует восстановления сетевого движка.
4. Уточняйте состояние реальной машины read-only командами, если задача касается установленного приложения. Проверка файлов ярлыков не подтверждает названия в работающем меню GNOME.

## Продукт и границы

- Название продукта: Zapret Manager. Команда и Python-пакет остаются zapret-console / zapret_console, чтобы сохранить совместимость. Актуальная версия указана в pyproject.toml и src/zapret_console/__init__.py.
- Интерфейсы: PySide6/QML и простое whiptail-меню. Textual удалён по решению владельца; не возвращайте его без нового запроса. --tui и --legacy-menu — скрытые совместимые варианты того же меню.
- Это управление отдельным движком nfqws. Удаление движка выключает обход и управление им. Не утверждайте, что интерфейс самостоятельно обрабатывает трафик.
- install.sh обновляет свой интерфейс без установки движка; setup.sh может скачать и установить адаптер, движок и стратегии. Не подменяйте одну операцию другой.
- remove-legacy-backend.py и restore-backend.py — специальные операции миграции владельца. Не запускайте их при обычном обновлении или переходе на новое устройство.

## Реализация и проверка

- Системные изменения проходят через core.admin_command, общую flock и доверенные пути. GUI использует client и revision/CAS. Не добавляйте произвольные root-команды, обход блокировок, eval конфигурации или повторы мутаций после conflict/busy.
- Сохраняйте конфигурацию адаптера, /etc/zapret-console и /var/lib/zapret-console при обновлении интерфейса. Изменение одного UI не должно запускать или останавливать сервис.
- Тесты работают в временных каталогах, systemctl/chown/авторизация подменяются. Используйте DESTDIR для install/uninstall. GUI проверяйте offscreen + software; пишите отдельно, был ли реальный визуальный/сетевой тест.
- Для изменения версии обновите обе декларации, CHANGELOG.md и проверки версии. Прогоните команды CONTRIBUTING.md и сборку scripts/build-release.py. Перед публикацией убедитесь, что тег совпадает с версией.
- Подробный отчёт сохраняйте в reports/<TASK>-report.md, в чат — короткий результат с фактическими проверками и ограничениями. Не выдавайте подготовку скрипта за выполненную операцию на host; active systemd не подтверждает работу Discord.

## Режим сотрудничества

Владелец попросил Codex работать самостоятельно. GLM и другие агенты не привлекаются без нового явного указания. Не откатывайте чужие изменения и незнакомые отчёты. Локальные commits допустимы. Push, тег и публикация разрешены для текущей задачи выпуска 0.3.3; для последующих публикаций требуется запрос пользователя. Не сохраняйте токены, ключи, пароли, локальные конфиги и приватные диагностические данные в Git.
